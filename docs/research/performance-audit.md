# 性能审计与修复记录

日期：2026-09-07。

## 范围

检查桌面命令、会话加载与摘要、工作区文件监听、Git 查询、聊天流式渲染、文件预览和构建加载。
保留审计开始前的未提交变更；本文仅记录本轮新修复，不将已有优化计入成果。

## 已确认的问题

1. 文件树在挂载每个子节点前线性扫描所有兄弟，平铺目录达到二次复杂度。复用路径索引去重，仅新节点挂载一次。
2. diff 的删除行队列反复 `shift()`，大段替换形成二次开销。改为游标读取，保留配对、行号及上下文语义。
3. 复制状态或样式变化重复高亮整段代码。按正文与语言缓存，行号改为一个文本节点，保留完整行号。
4. 文件预览标题栏间接导入语法高亮，未打开文件也加载全部语言。拆出轻量语言映射，文本和 diff 按类型懒加载。
5. 聊天正文增量触发无关的 Tiptap 配置执行。将编辑器隔离为 memo 子组件，回调通过引用读取最新状态。
6. 终端运行状态变化重复解析相同 ANSI 输出。缓存 ANSI 组件，正文变更仍重新解析。
7. 每次 RPC 更新复制所有状态集合，破坏未修改字段的引用稳定。使用不可变更新与结构共享，独立缓存扩展状态和组件数据。
8. 会话列表将每个 JSONL 文件的全部消息保留为 JSON 对象，随后仅提取摘要。改为逐行提取，保留首条摘要、最后活动时间、最新名称和计数。
9. 会话读取克隆活动消息，并同时传输完整历史和活动分支，前端只消费后者。改为移动活动消息，删除未使用的 IPC 字段，验证分支、缺失父节点及循环。
10. 会话列表、运行时预检、进程启动及会话重命名的同步命令占用桌面命令调用线程。列表进入阻塞池，其余耗时命令使用异步调度。
11. 文件扫描重复查询已知文件类型；嵌套构建和依赖目录的事件触发无效扫描。复用目录项类型，并让监听过滤覆盖各级被忽略目录。
12. Git 状态与工作区差异在同次请求重复解析 HEAD，干净仓库仍生成全工作区快照。干净状态直接返回零增删行；有变更时仅在本次请求内复用 HEAD 解析结果，保留未提交仓库、rename、快照和索引语义，不跨请求缓存。
13. 侧边栏逐项目过滤全部会话，复杂度为 O(项目数 × 会话数)。改为会话数组变化时单次分组，进程状态与分页变化不重新分组，保持原顺序和每页 5 条。
14. 大 diff 首次挂载所有行和高亮节点。使用 TanStack Virtual 动态行高列表，超过 200 行只渲染可见范围及预留行；内容不截断，复制仍使用原始全文。文档切换重置列表，宽度变化重新测量。

## 可复现测量

- 万文件构树：747.33ms -> 7.46ms。
- 三万行替换 diff 解析：84.94ms -> 6.44ms。
- 上述算法耗时为本机预热后五次中位数，不是用户端帧率或端到端延迟。
- 20 次聊天正文更新引起的 Tiptap 配置执行：20 -> 0 次（排除首次挂载）。
- 工具仅切换完成状态引起的相同 ANSI 输出解析：1 -> 0 次。
- 万行代码行号子元素：10001 -> 0，仍保留单个文本节点中的 10001 个行号。
- 1000 条大消息摘要：原来保留 1000 条完整消息，现在不保留历史消息，只保留摘要；解码 CPU 时间并未显著下降。
- 干净仓库状态查询：7 -> 1 个子进程；未提交的空仓库：6 -> 1 个。有 HEAD 的非空变更状态和工作区差异查询：7 -> 6 个；无 HEAD：6 -> 5 个。进程数量下降不代表耗时同比下降。
- 三项目、12 会话的分组字段读取：36 -> 12 次；进程和分页变化：0 次。
- Vite 最终生产构建入口：512.16KB -> 449.97KB；gzip：157.56KB -> 136.25KB。此口径为 Vite 自报值，按需块不计作入口。动态 diff 块含虚拟化库，共 27.90KB，未升级其他依赖。
- 大 diff 虚拟化前，3000 行替换在 jsdom 中生成 39006 个元素，同步挂载约 1353ms。此耗时不含浏览器布局和绘制。
- 最终实现的真实浏览器测试：800px 预览宽度、500px 面板高度、每 17 行一个长行时，稳定首屏挂载 24 行；380px 宽度挂载 12 行。与上述 jsdom 挂载耗时不是同一测量口径，不计算耗时比例。

独立浏览器 fixture 验证了 3000 行差异滚动至末行、800px/380px 面板宽度切换、长行折行和文档切换。稳定布局的相邻行无重叠、无横向溢出，末行底部与可视区域底部吻合。测试使用合成数据，不修改真实项目。

宽度变化的测量按 RAF 合并，卸载时取消；行高观察同样延后到动画帧。修复后往返调整宽度与滚动末尾，浏览器控制台和测试服务器均未再记录 ResizeObserver 循环告警。

审计开始前 `SettingsPage.tsx` 已使用原生 `button`，触发 `ui-boundary.test.ts` 的组件边界检查；发布前已替换为现有 `Button` 组件，保留图片选择行为，并通过全量回归。
